# Qwen2.5-0.5B TinyLoRA — Data Science Assistant

A [TinyLoRA](https://arxiv.org/abs/2602.04118) adapter that fine-tunes
[Qwen/Qwen2.5-0.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct) into a data-science
assistant: it answers data-science concept questions and writes runnable pandas / matplotlib /
scikit-learn / statistics / SQL code.

Unlike standard LoRA, which trains a pair of low-rank matrices `A`/`B` per target module, TinyLoRA
freezes a set of random projection matrices and trains only a small weighting vector `v` on top of
them:

```
ΔW = Σᵢ vᵢ Pᵢ
```

This adapter trains **21,504 scalars total** — `u=128` values of `v` per module, across 7 target
modules and all 24 transformer layers — against a ~494M-parameter base model, i.e. roughly
**0.004%** of the base model's weights.

Trained with the [tiny_lora](https://github.com/caglanakpinar/llm_with_tiny_lora) project.

## Training data

A synthetic data-science assistant corpus generated by the same project: concept Q&A plus runnable
pandas/matplotlib/scikit-learn/statistics/SQL tasks. The full corpus is ~2M records; this run trained
on a 50,000-sample subset with a 500-sample held-out split for eval, since TinyLoRA saturates its
~21k trainable scalars long before seeing the full corpus.

## Hyperparameters

| | |
|---|---|
| Base model | `Qwen/Qwen2.5-0.5B-Instruct` |
| TinyLoRA rank (`r`) | 2 |
| Vector width (`u`) | 128 |
| Weight tying | 0.0 (separate `v` per module) |
| Target modules | `q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj` |
| Trainable parameters | 21,504 |
| Optimizer | AdamW, `lr=2e-3`, cosine schedule, 45 warmup steps |
| Effective batch size | 32 (`per_device=8` × `grad_accum=4`) |
| Precision | bf16 |
| Early stopping | on eval_loss, patience 5 |

Full config: [`configs/sft_ds_assistant.yaml`](https://github.com/caglanakpinar/llm_with_tiny_lora/blob/main/configs/sft_ds_assistant.yaml).

## Results

Checkpoint at step 5750 (epoch ≈3.68), scored on the held-out eval split:

| | eval_loss | perplexity |
|---|---|---|
| Base model (no adapter) | 2.58 | ~13.2 |
| This adapter | 1.86 | ~6.4 |

Applying the adapter roughly **halves perplexity** relative to the un-adapted base model on this
held-out split, while training under 22k parameters.

## Usage

TinyLoRA is a new PEFT method, currently only available on PEFT's GitHub `main` branch (not yet in a
stable PyPI release):

```bash
pip install git+https://github.com/huggingface/peft.git
pip install transformers torch
```

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

base_model_id = "Qwen/Qwen2.5-0.5B-Instruct"
adapter_id = "Caglana/qwen0.5b-tinylora-ds-assistant"

tokenizer = AutoTokenizer.from_pretrained(adapter_id)
base_model = AutoModelForCausalLM.from_pretrained(base_model_id, torch_dtype="auto")
model = PeftModel.from_pretrained(base_model, adapter_id)

messages = [{"role": "user", "content": "How do I compute a rolling 7-day average in pandas?"}]
inputs = tokenizer.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt")
output = model.generate(inputs, max_new_tokens=256)
print(tokenizer.decode(output[0], skip_special_tokens=True))
```

## Limitations

- 0.5B base model: capable of short, focused answers but not competitive with larger models on
  complex multi-step reasoning.
- Narrow domain: tuned specifically for data-science Q&A and code generation; general-purpose chat
  quality is not a training objective.
- Identity/safety guardrails (e.g. not identifying as "Qwen"/"Alibaba") are implemented at the
  application layer in the project's [`chat.py`](https://github.com/caglanakpinar/llm_with_tiny_lora/blob/main/src/tiny_lora/chat.py)
  wrapper, not baked into the adapter weights — raw `generate()` calls against this adapter may
  surface the base model's own identity.
